## 0. 为什么先做狗

三条未武装的事件日志里，天气和燕子都是**背景**，狗是**活物**。

而且设计 4.1 把它写成了一条反向的刀：他 306 天成仙，狗陪了他 804 天，然后狗死了，他还活着。
"院比人长寿"是这个题材的正面，狗是它的反面——**人比狗长寿**。这一条不落地，日志体系就少一半重量。

代价是它必须在画面上真的动起来，否则第 96 天那句"篱笆底下钻进来一条狗，瘦"就是空话。

## 3. 三处翻车（都是美术，记下来免得重犯）

**① 尾巴和头长在同一边。**
第一版 `_facing` 只翻转头（`hx := 6.6 * _facing`），尾巴坐标是硬编码的 `-9.6`。
狗往左走时，头和尾巴一起挤在左侧，尾巴被身子盖住——**一只没有尾巴的狗**。
改法：`_draw()` 开头 `draw_set_transform(Vector2.ZERO, 0, Vector2(_facing, 1))`，整只狗镜像，所有坐标只按"朝右"写。

**② 站住不动时两条腿粘成一条。**
腿间距 1.4px、腿宽 1.4px，停下时（`s = 0`）两条前腿完全重合，看起来是一条粗腿。
改法：间距拉到 2.0px、腿宽收到 1.2px。**这个尺寸下"间距必须大于线宽"，否则看不见缝。**

**③ 趴姿翻了两次车。**
第一版头跟身子同一高度，加两只深色耳朵 = **一块插了两根钉子的木头**；
第二版把身子拉长 = **一根倒下的木头**；
第三版头颈抬起来、身子压短加厚（"面包"形），但耳朵又细又直 = **兔子**；
最后耳朵向外撇、并且**改用毛色不描边**（这个尺寸上深色三角会把整个头糊成一团，耳形只能靠轮廓认）。

美术是 M4 换贴图的范围，占位色块做到"看得出是只狗"就停手了，没有继续抠。

## 4. 一个设计取舍：狗的位置不存档

每次启动，狗都从篱笆那头重新走进来。

存一个 `x` 进存档的代价是：读档时它可能正好站在井上、田里、或者竹丛中间——
**为了一个像素级的连续性，换来一个必然出现的穿模**。而"它自己又钻进来了"这件事本身是自洽的。
天数 / 状态也不存：全部由 `logbook.current_day()` 现算，和日志那一套同源。

## 5. 日志引擎新增 `mark()`

`dog_door` 的条件是"狗第一次在墙根趴下"，日志引擎看不见狗——它只认 `tick_count`。

所以在 `logbook.gd` 加了一个通用口子：

```gdscript
func mark(when: String) -> void:
	if _hits.has(when):
		return
	_hits[when] = true
	_check_events()
```

`_check_events` 里 `craft:` / `offline_hours:` 之外的条件，一律落到 `_hits.has(when)`。
狗在第一次趴到墙根时发 `lay_at_door` 信号，`main.gd` 接一句 `logbook.mark("dog:door")`。

**为什么不让狗直接持有 logbook**：狗只认"天"（读 `current_day()`），不认"事"。
信号是单向的，日志引擎不需要知道狗的存在。将来天气、燕子走同一条路——把 `armed` 翻 true，接一句 `mark()` 就行。

剩下的 2 条（`rain_flood` / `swallow_leave`）文案一个字没动，等天气和燕子系统到位。
